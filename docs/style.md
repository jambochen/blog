# 文章風格

最後更新：2026-10-13

這份文件描述作者的寫作風格，給潤色或代寫文章的人（包含 coding agent）對照。術語見 [GLOSSARY.md](../GLOSSARY.md)。

## 樣本

寫之前先讀這一段，動筆時以它的語感為準。這是〈離開網頁對話〉前言的第一段，作者接受的版本：

> 近一年觀察同窗使用 ChatGPT 或 Claude，經常見到一些低效操作。比如需要修改 code 時，基本是將網頁上生成的 code 複製執行，等出結果後再將結果上傳，以此循環。如果是免費使用者，此為無奈之舉；但許多人明明持有付費帳號，卻僅僅是為了上傳更多圖片。實際上大部分功能並未充分使用，token 用量（token 是計算用量的單位）也未完全消耗，而已消耗的部分又多用於解析圖片、PDF 等非文字的視覺化文件。

完整的前言見 [leaving-web-chat.mdx](../src/content/blog/coding-agent/leaving-web-chat.mdx)。

## 語體：精煉

作者稱自己的風格為精煉：以最少的字把事情說清楚，讀者讀一遍就懂。

- **用詞選最常見的書面白話。** 同一個意思有幾種說法時，取日常最常用的那一個：也、都、應、就是、沒有、原因、看到、這件事。
- **連接詞用日常白話**：因此、所以、就是、如果、需要、而、但、卻。
- **長句。** 一句話以逗號、分號與連接詞串起數個分句，一個完整的意思寫成一句。
- **觀察者的語氣。** 陳述現象與做法，主詞用使用者、agent、工具的名稱；提到系列本身時以「本系列」作主詞。
- **技術詞留英文**，中英文之間空一格：code、token、context window。

## 用詞

- 用詞照台灣習慣。台灣用語與語體用詞的對照表都在 [scripts/check-wording.sh](../scripts/check-wording.sh)，檢查 `src/content/blog/coding-agent/` 之下不是草稿的文章；新增用詞規則時改這支腳本。
- 一律寫 code。「安裝程式」指 installer，「程式語言」指 programming language，都是另一個詞。
- 寫「函數」，因為讀者是做資料分析與科學計算的人，數學與科學計算的用語是函數。
- 泛指 file 時寫「檔案」。
- [GLOSSARY.md](../GLOSSARY.md)「文章用語」一節定的術語照原樣使用：規範檔、專案、提交、貫穿範例、skill。

## 比喻與解釋

比喻與概念的解釋取自任何科系的學生都有的經驗：考試、作業、課堂、報告。例如以背了大量考古題的考生說明 LLM 不理解原理也能答對。

讀者不限於統計系。統計的內容只出現在貫穿範例與各篇的分析實例裡，那是被處理的材料；解釋 LLM、agent 與工具時用日常的說法。

## 單篇可獨立閱讀

讀者可能由搜尋直接進入任何一篇。

- 術語在每一篇首次出現時以半句說明，不靠另一篇的定義。
- 前言不以其他篇為前提；跨篇引用放在正文用到之處，先寫出用得到的那一句，再附 wikilink。
- 連結是補充，不點也讀得懂。

## 直述

結論直接寫出來，不先鋪一個表象再翻轉。事物也不擬人，習慣不會「問」，工具不會「想」。

- 不寫：這些習慣看似無關，問的卻是同一件事，即專案換個地方還跑不跑得動。
- 寫：這幾個習慣都影響專案換個地方、換個時間還跑不跑得動。

內容也直接寫出來，不先預告它有幾條、有多簡單。

- 不寫：相對路徑的原則只有一條，凡是腳本裡出現的路徑，都從專案資料夾算起。
- 寫：相對路徑的原則是，凡是腳本裡出現的路徑，都從專案資料夾算起。

固定的揭曉用語列在 [scripts/check-wording.sh](../scripts/check-wording.sh)。

## 指稱項目

以名稱、連接詞與不編號的清單指稱項目，例如「做法之一是……」「另一個做法是……」「對不存在的函數與參數有抵抗力」。日後增刪一項時，其餘文字便不必跟著改。二級標題同樣以名稱開頭：「壞習慣：……」「規範檔新增規矩」。

跨篇回指同樣用篇名，以 wikilink 寫成「`[[版本控制]]`一篇」；不寫「第 3 篇」「上篇」，檔名與圖片檔名也不帶篇號。指稱一部時同樣用部名，寫成「『該知道的 CS 工具』一部」，不寫「第二部」。篇的先後只記在各篇 front matter 的 `seriesOrder`，增刪或調動一篇時，其餘各篇便不必跟著改。

數字留給本身固定的事物：有先後次序的操作步驟、介面上固定的數量（如三個分頁）、Anthropic 與 OpenAI「兩家」。

## 標題

全系列的二級標題已由作者確認，以 `src/content/blog/` 裡的為準。新增或修改標題時比照既有的寫法：

- 名詞短語：「模型規模與 effort」「網頁對話與 coding agent 之別」。
- 主詞寫出名稱：「由 agent 起草初版」。
- 技術詞留英文，中英文之間空一格：「權限提示與 plan mode」。
- front matter 的 `title` 是純文字，直接寫字，例如 `title: LLM 與 agent 的運作原理`。

## 潤色

潤色是讓語句更通順，語體、用詞與句子的長短維持作者原樣。可以調整資訊的順序。

作者原稿改成上面那段樣本時動的地方，就是潤色的尺度：

- 釐清主詞，讓讀者分得出是誰在做什麼。
- 刪去重複的詞。
- 把指涉不清的代詞換成它所指的東西，例如「其中」改成「已消耗的部分」。
- 補上逗號與中英文之間的空格。
- 用詞換成台灣的說法。

作者自己選的詞照原樣保留，例如同窗、此為無奈之舉。

潤色稿與成批的替換先給作者看，確認後才寫進文章。
